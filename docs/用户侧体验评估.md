# 用户侧体验评估：好用吗？易用吗？复杂吗？比传统 RAG 多了什么？

> 视角声明：本文不看演示、不谈评委——只坐在三类真实使用者的椅子上，以使用身份拷问这套构思。诚实优先，先说好处也说抱怨。
> 配套：[落地可行性与成本总览.md](./落地可行性与成本总览.md)（工程视角）· [CONTEXT.md](../CONTEXT.md)（系统内部语言）。

---

## 0. 先分清「使用者」到底是谁

BetterRAG 的特殊性：**知识库的直接消费者是 Agent**（检索 API 的调用方），人类用户分两层，且两层看到的界面完全不同：

- **提问者**（核心用户）：通过客服 Agent 提问的坐席与最终客户。他们看到的一切 = 答案 + 来源标注 + 👍/👎。
- **管理员**（重用户）：业务专家、知识运营者。他们看到的一切 = 审核队列 + 报告 + 处置按钮。

这个分层是全篇的钥匙：**系统的复杂性是真实的，但每层用户只暴露必要子集**——下面逐层验证这句话是否成立。

---

## 1. 提问者视角：四问四答

### 好用吗？——「剪刀差曲线」决定的一切

诚实的判断是分时段的：

| 时段 | 体验 vs 传统 RAG |
|---|---|
| 第 1 天 | **≈ 打平，甚至略重**：答案质量相同，但多了标注要读 |
| 第 90 天 | **剪刀开始张开**：传统 KB 开始腐烂（没人清理过期知识），BetterRAG 开始代谢（旧知识自动退场、新知识已就位） |
| 第 365 天 | **差距不可逆**：一个越用越脏，一个越用越干净 |

单次问答的质量与传统 RAG 打平（检索引擎相同）；用户可感知的差异在**答案可信度**这个传统 RAG 完全缺失的维度上。BetterRAG 的用户收益是一条随时间张开的剪刀差——这个诚实框架同时说明了收益**何时**可感知：**集中在知识半衰期短的域**（资费、政策、价格）；在恒定域（产品手册、操作 FAQ），用户几乎无差别体验，但也不会更差。

### 易用吗？——零迁移成本 + 零学习成本

- 提问交互与传统 RAG **完全一致**：输入问题，得到答案。不改变任何肌肉记忆。
- 新增交互只有两样：读一个标注、点一个按钮。都是零学习成本的原语。
- **易用性不是这套系统的问题；标注的「心理效应」才是**——同一个标签，文案设计决定它是「答案的体检报告」还是「免责声明」（详见第 3 节）。

### 复杂吗？——唯一新增认知：信任标注

用户需要理解的概念只有一个：**「这条答案里有一部分是新鲜的」**。注意：用户不需要理解「学习区/预备区/稳定区」——那是我们的内部语言（第 4 节的术语分层原则）。普通用户对「新知识（待专家复核）」的理解成本 ≈ 食品包装上的生产日期。

### 新吸引点在哪（相较传统 RAG，按用户可感知度排序）？

1. **答案自带体检报告**——传统 RAG 的所有引用同等可信（黑箱自信）；BetterRAG 让用户第一次**分级信任**答案。对高风险决策（钱、合规）的提问者，这是决定性的：他们宁要「带标注的诚实」，不要「无标注的自信」。
2. **新知识零等待**——传统企业库：新政策发布 → 等录入 → 等审核 → 才能被正确回答（天/周级）；BetterRAG：Agent 收纳当天可用（带标注）。时间敏感场景里这是**从周到天**的体验跨越，且是第一天就能感知的差异。
3. **反馈被看见**——传统 RAG 里点赞石沉大海（给产品团队的数据）；BetterRAG 里 👍 是知识块的晋升燃料，用户的反馈**真实地改变知识库**。配套设计（产品阶段）：「你上月点赞的《新套餐政策》已通过专家审核」——参与感闭环，用户从消费者变共建者。
4. **不被旧答案坑**——剪刀差的长期面：不会一本正经地用半年前停售的套餐回答新用户。
5. **（产品阶段）新旧对决的投票权**——重大知识更替时用户有发言权，影子对决把「系统升级」变成「社区事件」。

## 2. 管理员视角：四问四答

### 好用吗？——从修理工变法官

传统知识库管理员的隐性工作清单：追查哪篇文档过期、人工比对新旧政策冲突、定期清理僵尸文档、猜测哪条知识没人用了——**全是救火**。BetterRAG 把这些全部自动化，剩下的显性工作是：

- 审核台：**选择题**（AI 已出好摘要、差异对比、冲突高亮，管理员点通过/拒绝/修改）；
- 报告驱动：降级原因报告、矛盾台账、晋升存活率——**系统主动汇报，人只裁决疑难**。

### 易用吗？复杂吗？——复杂度其实是下降的

界面原语：队列 + 标签 + 按钮 + 报告，无公式无参数（那是 config 和开发者的领地）。心智模型从「文档管理员」升级为「知识治理者」——学习曲线存在，但被报告的透明性补偿（每个状态变化都有原因可查：为什么衰减、为什么冲突、为什么晋升）。

### 一个诚实的风险：AI 预审的信任校准

AI 审核摘要如果错了，会诱导管理员「盲目一键通过」——**管理员过度信任 AI 预审是新的系统性风险**。缓解：摘要必附原文锚点、冲突高亮可点击跳转原文、审核台对「有冲突史」的块强制展示深度复审标签（已在规格）。

## 3. 诚实清单：用户会抱怨的五件事

1. **标签的免责声明效应**：「⚠ 来源：学习区」会被负面解读（"这答案不可靠？"）。缓解三重：正面文案（「新入库知识，3 天前，待专家复核」而非「低信任」）、可折叠、默认只在含新知识的答案中出现。
2. **答案漂移感**：同一个问题，今天的答案和上周不一样（知识在升降）。用户困惑点：「到底哪个对？」缓解设计——**变化通知**：「此答案基于比上次更新的知识（12 月政策已更新）」——把漂移翻译成进步叙事。
3. **探索召回的个别劣化**：探索席把低置信块放进 top-k，换来晋升机制的曝光前提，代价是**个别答案引入了可能错误的新知识**（传统 RAG 不会）。缓解：探索席强制标注 + 高合规域可关闭探索（信任分级订阅的第二个用途）。
4. **影子对决的打扰**：频繁弹「帮我选更好的答案」会烦。缓解：每用户频率上限 + 可跳过 + 只在高价值冲突时触发。
5. **冷启动的标签过剩**：新库满屏「新知识」标注——**标注的价值与稀缺性成正比**，90% 答案都带标注等于没有标注。缓解：管理员导入通道在第一天就装满稳定区（这正是冷启动通道的第二重意义：不仅保答案质量，还保**标注的信号纯度**）。

## 4. UX 三原则（本次评估的产品化输出）

1. **术语分层**：系统内部语言（CONTEXT.md 的 26 个词条）**永不原样泄漏进用户界面**。用户语言是结果，不是机制：

   | 内部术语 | 用户界面词汇 |
   |---|---|
   | 稳定区 | 已验证（专家已复核） |
   | 预备区 | 复核中 |
   | 学习区 | **新知识**（入库 X 天）——绝不出现「学习区」字样 |
   | 铁律 | 官方权威 |
   | 影子模式 | 新旧版本对比 |
   | 置信度数字 | 分级色带，不显示数字 |

2. **复杂度内化**：用户只见按钮和报告，公式是开发者的领地。类比：自动挡比手动挡更复杂（变速箱），但驾驶更简单——「功能机更简单」是错觉。
3. **反馈闭环**：让用户看见自己的 👍 改变了什么。反馈被看见的瞬间，用户从消费者变成共建者——这是 Wikipedia 编辑者心理的知识库版。

---

## 5. 一句话总结（每个角色一句）

- **对提问者**：提问体验与从前完全一样，但答案多了一份体检报告——且从第 90 天起，这份报告越来越值钱。
- **对管理员**：从追着过期文档跑的修理工，变成只裁决疑难的法官。
- **对「复杂吗」的最终回答**：复杂性没有消失，是**系统自己把它消化了**——这正是「好用」的工程定义。

> 工程侧注记：第 4 节的 UI 词汇映射表应在实现三页面时直接进规格 §10；第 3 节的五项缓解（变化通知、探索标注、频率上限、稀缺性守护）应随档位选定后进 demo 实现清单或产品路线图。
